# ITWASATV — standalone ITSATV

Статический перенос ITSATV: HTML, CSS и читаемые JavaScript-модули. Никаких PHP, Firebase, базы данных, сборки, компактификации, аналитики, Sentry, VK SDK или собственного сервера в production. Достаточно загрузить файлы в GitHub Pages.

## Версия

Текущая версия — **0.1.9**. `0.1` — версия standalone-проекта; третья цифра увеличивается с каждым коммитом изменений, начиная с переноса (сейчас девятый). Перед следующим коммитом нужно обновить её в `package.json` и `js/config.js`. Это не требует сборки.

## Запуск

Нужен Node.js 22+ только для локальных утилит:

```sh
npm start
```

Открыть http://localhost:8080/itwasatv-open/ (или корень сервера). `npm install` не нужен: зависимостей npm нет. Также подходит любой статический HTTP-сервер. Открытие `index.html` через `file://` не поддерживается: загрузка модулей, JSON и YouTube требует HTTP(S).

За основу взят `ITSATV_APP/index.html` с логикой `itsatv-dev.js`, затем перенесены каталог, FRESH и оформление из финальной версии **0.16.0** в `/Users/dmitry/_DEV/itsatv-dev-docker/src` (июль 2025). Экспериментальный `index-login.html` не используется. Исходный `itsatv.css` сохранён без изменений. В частности, сохранён CSS-хак `.video-foreground, .video-background iframe` (`top: -100%; height: 300%`) и медиазапросы с шириной `300% / left: -100%` и `120% / left: -10%`, обрезающие края видеоплеера. Корректировки работоспособности вынесены в `standalone.css`.

Сохранены экран приветствия, SVG-логотипы, меню справа, панель настроек, три колонки программы, титры и сведения о клипе. Удалены отсутствующий account-диалог, серверная сессия, админский помощник добавления роликов и VK-ссылка. Избранное и отдельный компактный интерфейс удалены. Поиск использует исходное окно и список результатов.

Библиотеки находятся рядом с сайтом:

- UIkit **3.0.0-rc19**: CSS, JS и соответствующий пакет иконок;
- Font Awesome **5.0.13**, исходный SVG/JS bundle;
- normalize.css и shuffle-text из ITSATV.

Новые стили/фреймворки/CDN не нужны. Сеть во время работы используется для YouTube и двух публичных источников времени. API key не нужен плееру и не расходует квоту во время просмотра.

## Управление

- логотип / стрелка под ним: показать и скрыть меню;
- значок часов: программа трёх соседних каналов; заголовки переключают каналы;
- шестерёнка: громкость, b&w, подсветка, upcoming, пауза, синхронизация и about;
- меню у названия клипа: музыкальные сервисы и сведения;
- `←` / `→`: предыдущий / следующий канал;
- `Space`: пауза / продолжить с текущей позиции общего эфира;
- `L`: программа; `F`: fullscreen; `M`: mute; `S`: синхронизация;
- `Ctrl+X` / `Ctrl+F`: поиск; `T`: about; `U`: статус.

Сочетания не перехватываются в полях ввода. Во всех размерах окна используется обычный интерфейс; параметры `?smallui` / `?smallUI` больше не переключают оформление. На низких окнах уменьшены отступы обычной панели справа; при нехватке места она прокручивается. `?channel=7` выбирает восьмой канал; нумерация URL начинается с нуля.

## Расписание и синхронизация

`data/videos.json` содержит все **854** записи из финального `itsatv-dev-docker/src/core/videosarray.php`, с названиями, длительностью, годом, жанрами, флагами оформления и съёмочной группой. SQLite не нужен. Строковые `"false"` и `"true"` нормализованы; Hip-Hop приведён к единому регистру.

`js/schedule.js` заменяет `videos.php`, `itsatv.php` и `getlineup.php`. Сохранены 21 канал (индексы 0–20), недельная ротация Main, фильтры Rock/Indie, Pop, Electronic/Pop, Ambient, первые 115 клипов ITSATV 2018, Classic, Hip-Hop, Funk/Soul/RNB, пороги просмотров, FRESH (канал 12, релизы с 2023 года) и канал с black-флагом. Каналы без отдельного фильтра, как в оригинале, используют весь каталог с разными seed.

Fisher–Yates перемешивается один раз с seed `UTC-дата:канал`. Порядок не зависит от сессии, часового пояса браузера или повторных запросов. Это исправляет повторное перемешивание PHP session-кеша; старый порядок PHP намеренно не воспроизводится. Позиция эфира — `epoch % суммарная длительность`, включая корректные границы 0 и конец цикла. На UTC-полуночи порядок меняется одновременно для всех. Названия времени в программе отображаются в локальном часовом поясе зрителя.

`js/clock.js` запрашивает UTC у TimeAPI.io и worldtime.timezone.io, выбирает успешный ответ с наименьшей задержкой и учитывает половину времени запроса. Далее ход времени отсчитывается монотонными часами `performance.now()`. Обновление — раз в 15 минут, после возвращения из долгого сна/фонового режима и по команде sync. Таймаут — 4 секунды. При недоступности источников сохраняется предыдущая синхронизация; при первом запуске используется время устройства. Источник времени не выводится в стартовом уведомлении.

Каждые полсекунды проверяется расписание. Дрейф воспроизведения больше 4 секунд исправляется seek; есть пауза, корректное возвращение к эфиру, смена трека и ограничение повторов при ошибках. На недоступном в данном браузере клипе показывается следующий, затем плеер возвращается к общей шкале на границе слота. Региональные различия не меняют общий плейлист.

Удалены старые глобальные findSong/callfindSong-обёртки и перебор тысяч виртуальных каналов. Поиск фильтрует локальный каталог; выбранная песня воспроизводится один раз, затем возвращается общий эфир. В URL доступны только реальные каналы 0–20.

## Проверка доступности видео

```sh
npm run check-videos
npm run check-videos -- --write
npm run check-videos -- --region=RU
npm run check-videos -- --limit=50
```

Утилита запрашивает YouTube Data API пакетами по 50 ID: существование, возможность embedding и региональные ограничения. Исходный публичный demo API key находится в `js/config.js`; можно передать `YOUTUBE_API_KEY` через окружение. Отчёт — `reports/video-check.json` (не отслеживается Git). `--write` обновляет `data/availability.json`; каталог `videos.json` не удаляется и не переписывается.

На 24.10.2026 проверены 854 ролика из финального каталога: 3 отсутствуют / закрыты, 851 разрешён для embedding по данным API. Список исключений включён в репозиторий. Региональная недоступность и возрастные ограничения всё равно могут препятствовать фактическому воспроизведению.

Резервная команда `npm run check-videos -- --oembed` проверяет существование через oEmbed, но не подтверждает возможность встраивания; `--write` с ней запрещён. При недействительном ключе основной checker явно сообщает об ошибке и не публикует ложные результаты.

## Хранение и YouTube

Приложение не читает и не пишет cookies. Настройки и последний канал хранятся в `localStorage` с префиксом `itwasatv:`; при запрете хранилища используется память текущей вкладки. Загрузка времени выполняется с `credentials: omit`.

Для iframe выбран privacy-enhanced домен `youtube-nocookie.com`; YouTube сам может использовать своё хранилище/данные после начала воспроизведения. Абсолютного отсутствия cookies от внешнего плеера это не гарантирует. Указаны фактический `location.origin`, `playsinline`, разрешения и `strict-origin-when-cross-origin`. Это устраняет привязку к старому домену и типичную ошибку 153 из-за отсутствия Referer; ограничения сети/региона всё равно возможны.

Справка YouTube: https://developers.google.com/youtube/iframe_api_reference и https://support.google.com/youtube/answer/171780 .

## Уточнения интерфейса

Восстановлена исходная настройка Font Awesome `autoReplaceSvg: nest`: CSS малых/больших иконок рассчитан на SVG внутри `i`. Отступы основного CSS не меняются. Lineup снова использует исходный `z-index: 5` под кнопками `99`; остальные диалоги и настройки остаются выше кнопок. Подсказки скрываются при нажатии и открытии панелей, не перехватывают мышь и не накрывают панель.

Уведомления повторяют тёмное оформление Alertify и закрываются нажатием, без подключения ещё одной библиотеки. Стартовый статус показывается сверху справа на 15 секунд: версия, общее число/длительность клипов и последний добавленный клип, как в оригинальном `showsmallstatus.php`; остальные уведомления остаются слева. Строки про timezone/источник времени нет. На паузе остаётся исходная заставка, случайный текст PLAY удалён. Upcoming снизу по центру, как в 0.16.0, показывается один раз при остатке менее 27 секунд, на 10 секунд.

При открытии страницы эфир автоматически запускается без звука за приветственным окном через один `loadVideoById()` без последующего `playVideo()`. PLAY/UNMUTE закрывает окно и включает звук уже играющего ролика без перезагрузки. При короткой паузе вызывается только `playVideo()`, при долгой — сначала `seekTo()` к эфиру. `cueVideoById()` не вызывается. После PLAYING добавлена запрошенная задержка 500 мс, затем скрывается заставка и начинается исходное секундное появление изображения. Повторная буферизация уже видимого видео не возвращает заставку. Iframe исключён из фокуса. Исходная обрезка краёв iframe сохранена. Центральное содержимое чужого iframe недоступно CSS сайта; отдельного документированного параметра для этой кнопки у YouTube нет.

Начальные титры запускаются один раз после 5-й и до 20-й секунды фактического времени видео: появление за 1 секунду, начало исчезновения через 5 секунд от запуска, исчезновение за 0,8 секунды. Диапазон 5–20 секунд — окно запуска, а не продолжительность показа. Позднее подключение к эфиру не вызывает запоздалых начальных титров.

Удалены модальное окно Favorites, сердечко компактного плеера, кнопки добавления в сведениях о клипе, клавиша A и вся логика чтения/записи избранного. Настройки громкости и канала сохраняются как раньше.

Восстановлены исходные цвета: кнопки и текст сведений о клипе `#eee`, заголовок финальных титров `#fff`; для клипов со светлым фоном сохранены тёмные цвета. В 0.1.9 подсказки также следуют инверсному оформлению: `#111`, как у кнопок. Вертикальный отступ между кнопками увеличен с `1.6rem` до `1.8rem`. ShuffleText работает только в Lineup, приветствие больше не анимируется.

Параметры iframe сверены с оригиналом: `controls: 0`, `iv_load_policy: 3`, `cc_load_policy: 0`, `rel: 0`, `playsinline: 1`, `enablejsapi: 1`; `origin` соответствует текущему сайту. `disablekb: 1` оставляет управление клавиатурой приложению. Параметра `hideui` в исходнике нет; исходный `modestbranding: 1` больше не влияет на плеер согласно [документации YouTube](https://developers.google.com/youtube/player_parameters#modestbranding).

## Проверка последовательности команд YouTube (0.1.6)

Убраны принудительные перезагрузки того же ролика при PLAY, sync, восстановлении сети и возврате во вкладку. `tune()` продолжает проверять расписание раз в 500 мс, но загружает видео только при новом слоте или явном повторе после ошибки. Синхронизация исправляет позицию через `seekTo()` только при расхождении более 4 секунд. Повторные клики во время загрузки не отправляют команды заново.

`videoRevealDelayMs: 500` в `js/config.js` задаёт задержку после PLAYING. Пауза, смена канала и ошибка отменяют старый таймер; повторный PLAYING не продлевает его. Если буферизация началась до первого показа, отсчёт начнётся заново после следующего PLAYING. Звук в течение этих 500 мс уже может идти.

Для независимого сравнения откройте `/itwasatv-open/tools/playback-probe.html` на локальном сервере. На одном и том же видео можно выбрать `cue → load`, одиночный `load`, `cue → play` и задержку 0/500 мс. Страница показывает команды и события с временем в миллисекундах (новые сверху), запускается без звука и сохраняет исходную обрезку iframe. При RESUME в режиме `load` сохраняет позицию, чтобы отдельно проверить `playVideo()`; SYNC намеренно возвращает к 30-й секунде. Это отдельная диагностическая страница; основной интерфейс не содержит журнала или дополнительных запросов.

Результат сравнения в Chrome 25.10.2026: `cue → load` и одиночный `load` запускают видео, но первый вариант при повторном PLAY заново загружает клип. После единственного `playVideo()` при возобновлении (без `cue` / `load` / `seek` между паузой и PLAYING) центральный значок также появился. В варианте с задержкой журнал показал PLAYING на 62586 мс и открытие картинки на 63087 мс: 501 мс. На первых видимых кадрах значок ещё оставался. Это подтверждает, что лишние команды можно и нужно убрать, но задержка 500 мс не гарантирует полного скрытия элемента YouTube. Измерение относится к одному браузеру и видео; анимация внешнего плеера может различаться.

## Фоновое воспроизведение за приветствием (0.1.7)

Восстановлен автоматический запуск без звука при готовности плеера, как в Docker-версии. Приветствие остаётся открытым поверх видео; заставка снимается через 500 мс после PLAYING. Титры и основные кнопки появляются после нажатия PLAY/UNMUTE. Этот переход включает звук с выбранной громкостью и сохраняет уже играющий ролик, в том числе запасной клип после ошибки. Если браузер запрещает автозапуск, остаётся заставка и кнопка PLAY для повторной попытки по нажатию.

На нескольких других клипах сам YouTube сообщил о региональной недоступности. Центральный значок YouTube остаётся отдельным ограничением внешнего плеера.
